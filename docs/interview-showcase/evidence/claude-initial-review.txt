**Headline: two proven transparency gaps and one proven grounding gap, plus several limitations.** Everything below is from static reading of the code. Nothing here proves live behavior, and I ran nothing.

## Proven bugs, ranked

**1. The About page claims human review that the code does not perform.** This is the most interview-sensitive finding.

  • **What the public copy says.** `app/about/page.tsx:597-602` says "Publication means a reviewer confirmed the source and quote." Lines 676-678 say "a reviewer name and timestamp are stored before any fact can be published or supplied to Ask."

  • **What the code does.** `lib/biography-queries.ts:45-47` and `lib/elections/queries.ts:517-520` both carry the comment "Human review was retired" and publish everything whose status is not `rejected`. New rows are written as `needs_review` in `scripts/ingest/member-biographies.ts:316` and `scripts/ingest/candidate-sites.ts:435`, then published immediately.

  • **The model is told the same falsehood.** The tool description at `lib/ask-tools.ts:163` says "human-reviewed biography facts." The assistant can repeat that to readers.

  • **Minimal fix.** Rewrite both About paragraphs and the tool description to the true safeguard: verbatim quotes are checked against the stored page snapshot in code, published without human review, and removable on report. The snapshot check is real (`lib/biography-research.ts:75-77`, `lib/elections/campaign-research.ts:161`), so say that instead.

  • **Test.** A doc-consistency test that fails if the About page or any tool description contains "reviewer" or "human-reviewed" while the publish filter is `<> 'rejected'`.

**2. The "answered" gate counts attempted lookups, not successful ones, and never requires a citation.**

  • **Evidence.** `lib/ask-engine.ts:414` pushes to the trace before the tool runs. Line 424 swallows failures into a generic error payload. Line 198 then accepts status `answered` on trace length alone. The OpenAI path repeats this at lines 528 and 538.

  • **Citations are optional in practice.** `lib/ask-citations.ts:262` silently strips unknown refs. Coverage is only logged at `app/api/ask/route.ts:204`. An `answered` reply with zero valid citations is served and cached for 24 hours.

  • **Public claims contradicted.** About says "rejected unless at least one record lookup was completed" (line 619-620). The Ask footer says each factual answer "requires a fresh lookup and a valid record citation" (`components/ask-client.tsx:1265`). Neither is enforced.

  • **Concrete path.** In state scope the model calls `get_delegation`, then answers a vote question from memory with invented refs. The refs are stripped, the answer ships uncited as `answered`, and the cache replays it to other readers.

  • **Minimal fix.** Count successful retrievals as registry size or non-error results. Require at least one for `answered`. Require at least one resolved citation for `answered`, or downgrade the status to a visible "uncited" label and skip the cache write.

  • **Tests.** Export the terminal-answer check and test: failed-only trace plus `answered` throws; `answered` with zero surviving markers is downgraded or rejected; zero-citation results are not cached.

**3. The link sanitizer lets the model invent official URLs.**

  • **Evidence.** `lib/ask-engine.ts:80` passes any `https://congress.gov/...` or `https://fec.gov/...` link through without checking it against retrieved evidence. No tool result contains such URLs, so every one is model-generated.

  • **Fix.** Keep the link only if the exact href appears in the evidence string. Otherwise reduce it to plain text like the other branches.

  • **Test.** Extend the existing sanitizer test at `tests/ask-security.test.ts:136` with a fabricated congress.gov link and assert it collapses to text.

**4. The Anthropic fallback can report "No matching record" when no lookup was possible.**

  • **Evidence.** `lib/ask-tools.ts:248-256` selects tools by regex. Words like "spent," "expenditure," "amendment," "measure," "veteran," and "college" match no route. In member scope with no match and no "record/work/about" word (line 274), the model receives only `submit_answer`.

  • **Effect.** The model cannot retrieve, so it returns `not_found`, and the UI labels it "No matching record" (`components/ask-client.tsx:1174`). That is a statement about the data the system never checked.

  • **Fix.** When the router selects no retrieval tool, fall back to the full scoped tool set, or return a distinct "could not route this question" status rather than `not_found`.

  • **Test.** The router test at `tests/ask-security.test.ts:83` only checks positive matches. Add negative cases asserting a retrieval tool is always present in member scope.

## Limitations, not bugs

  • **Third-party text enters the model unscreened.** Campaign and official-site quotes flow into tool results with only a prompt instruction as defense (`lib/ask-engine.ts:49`). The attack-signature check runs on questions and history only. A candidate controls their own site, and a successful injection in state scope would be cached for a day. Suggested fix: run the signature check on quotes at extraction time and on tool payloads before they reach the model, with a fixture test.

  • **"Coming feature" wording on trades is misleading.** The prompt (line 47) and About (line 476) call stock disclosures a coming feature while `/trades`, the RSS feed, and the CSV exports are live. Say "not available through Ask" instead.

  • **Citations land on page sections, not records.** A vote citation links to `/member/ID#votes` (`lib/ask-citations.ts:168`). A topic-searched historical vote may not appear in that section. Linking the roll-call source directly would make a journalist's verification one click.

  • **Cache can outlive the data.** Answers cache for 24 hours keyed by prompt version only (`lib/ask-limits.ts:155-166`). A nightly ingest that retires a member does not invalidate yesterday's answer.

  • **Minor copy issues.** `components/ask-client.tsx:1235` shows "Answered from the delegation roster" for any zero-trace reply, including declined ones. The prompt calls the site "journalist-built" while GOALS.md describes a developer's portfolio.

## Human touchpoints, stated plainly

No content is human-reviewed before publication anywhere in the current system. The Ask footer discloses this honestly. The About page does not for biography and campaign quotes, which is finding 1. Post-publication touchpoints are a mailto link, the keyed `/admin/ask-log` page, and two optional review scripts that nothing depends on.

For the interview, the defensible story is: deterministic scope locks, server-validated citations, snapshot-verified quotes, a 90-day audit log, and no human in the loop. Fixing finding 1 first keeps that story truthful.
